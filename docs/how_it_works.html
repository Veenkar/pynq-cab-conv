Inside the Cab Convolver

How a guitar signal gets through the PYNQ-Z2: what taps and lanes are, what the four DSP slices do every 20.8 µs, and how I2S moves samples between the FPGA and the codec.

The whole path

The codec (ADAU1761) turns the analog amp signal into 24-bit numbers 48 000 times a second and sends them to the FPGA over I2S. The FPGA logic (the PL) convolves each sample with the cabinet's impulse response and sends the result back to the codec's DAC and headphone amp. The ARM cores running Linux (the PS) never touch the audio in real time. They only set registers, load the IR coefficients and read the recording ring.

What a tap is

An impulse response is a recording of what the cabinet does to a single click. At 48 kHz it is a list of numbers, one every 20.8 µs. Each of those numbers is a tap, also called a coefficient, written h[k]. Convolution makes every output sample a weighted sum of the current input and the inputs before it, with the IR as the weights:

y[n] = h[0]·x[n] + h[1]·x[n−1] + … + h[8191]·x[n−8191]

The name comes from the classic drawing of this filter: a chain of one-sample delays (z⁻¹) with a "tap" after each delay, where the signal is picked off, multiplied by its coefficient and added in.

Why 4 DSP slices (not 8)

The current build uses 4 DSP48 slices. 8 would be the NLANE = 8 extension, which doubles the IR to 16 384 taps. The count follows from the arithmetic: there are 8192 multiply-adds per sample, and one DSP slice does one per clock.

393.2 Mmultiply-adds per second (8192 × 48 kHz)
122.88 Mmultiply-adds per second per DSP (1 per clock)
3.2 → 4DSP slices needed, rounded up to a power of two
2560clock cycles available per sample

A DSP48 is a hard multiplier-accumulator block in the Zynq fabric (the Z-7020 has 220 of them). One slice multiplies a 24-bit sample by an 18-bit coefficient and adds the product into a 48-bit accumulator, and it can do this every clock cycle because each stage has its own pipeline register:

rtl/fir_engine.v · written so Vivado maps it onto one DSP48 per lane
// ---- MAC pipeline: A/B regs -> M reg -> P accumulator (DSP48) ----
reg signed [DW-1:0]    a_r;
reg signed [CW-1:0]    b_r;
reg signed [DW+CW-1:0] m_r;
reg signed [AW-1:0]    acc;

always @(posedge clk) begin
    a_r <= dl_rd;
    b_r <= cf_rd;
    m_r <= a_r * b_r;
    if (state == S_RD1)
        acc <= {AW{1'b0}};
    else if (v3)
        acc <= acc + {{(AW-DW-CW){m_r[DW+CW-1]}}, m_r};
end
assign acc_w[k] = acc;

Lanes

A lane is one DSP slice plus the memory it reads: a 2048-sample slice of the input history and the matching 2048 coefficients. The 8192 taps are split into four consecutive blocks of 2048 (each block covers 42.7 ms of the IR), and the four lanes work on them at the same time. Each lane steps through its 2048 addresses one per clock. Then the four partial sums are added, shifted and clipped to 24 bits.

Two coefficient banks. Every lane holds two full sets of coefficients. The driver writes a new IR into the bank that is not playing, then flips one bit. The engine switches on the next sample boundary, so changing the cab never produces a half-old, half-new filter or a click.

Scaling. FPGA arithmetic is integer, so the IR is stored as h = hq / 2shift, with hq an 18-bit integer. The driver picks the largest shift that still fits 18 bits and can't overflow the accumulators. That shift is the "≫" at the end, and each bank keeps its own.

sw/cab_conv.py · choosing the shift
shift = int(math.floor(math.log2(CMAX / peak)))
shift = max(0, min(63, shift))
while True:
    hq = np.clip(np.round(hp * 2.0 ** shift), -CMAX, CMAX).astype(np.int64)
    lane_l1 = np.abs(hq).reshape(-1, ltaps).sum(axis=1).max()
    if lane_l1 * (1 << (DW - 1)) < (1 << (AW - 1)) or shift == 0:
        break
    shift -= 1
return hq, shift

I2S: how samples reach the codec

I2S (Inter-IC Sound) is a three-wire serial link for audio between chips. One device is the clock master; here that is the FPGA, and the codec follows. Samples travel one bit at a time, most significant bit first.

BCLK
bit clock, 3.072 MHz. One data bit per period: 64 periods per stereo frame, 32 per channel.
LRCLK
word select, 48 kHz. Low while the left sample is sent, high for the right. One full period is one sample frame.
SDATA
the bits themselves. There are two lines: ADC → FPGA, and FPGA → DAC.
MCLK
master clock for the codec's converters, 12.288 MHz = 256 × 48 kHz. Not part of I2S proper.
rtl/i2s_master.v · BCLK, LRCLK and data from one phase counter
// BCLK: low in the first half of the bit, high in the second
bclk_r <= (ph >= HALF);

// launch LRCLK and data at the start of each bit (falling BCLK)
if (ph == 0) begin
    lrclk_r <= bitn[5];
    if (bitn == 6'd0) begin
        // frame boundary: hand over received words, latch tx
        rx_l       <= sh_l;
        rx_r       <= sh_r;
        frame_tick <= 1'b1;
        tl         <= tx_l;
        tr         <= tx_r;
        sdo_r      <= 1'b0;             // slot 0 = I2S delay bit
    end else begin
        sdo_r <= txbit(bitn, tl, tr);

Recording

The capture ring is a BRAM of 8192 frames (170.7 ms). While REC is on (BTN0, or a register bit), every frame stores the selected input and the FIR output for the same sample. Linux reads whatever is new about every 20 ms over AXI4-Lite and appends it to two mono 24-bit WAVs, one dry and one wet, sample-aligned. The ring gives Linux eight times more slack than it needs, so in testing no frame was lost.

wire cap_we   = r_rec && !rec_rise && y_done;   // x_dly belongs to this y

Glossary

PL / PS
Programmable Logic (the FPGA fabric) and Processing System (the two ARM cores and their DDR, SD and USB).
BRAM
block RAM: 36 Kbit memory tiles inside the fabric. The Z-7020 has 140; this design uses 26 (14 for audio, 12 for the recording ring).
MAC
multiply-accumulate, acc += a·b: the one operation an FIR filter is made of.
AXI4-Lite
a simple memory-mapped bus. Linux reads and writes the design's registers as if they were memory at 0x43C00000.
z⁻¹
a one-sample delay, in signal-processing notation.
IR
impulse response: the cabinet + mic + room captured as a list of taps.
